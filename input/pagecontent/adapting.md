This page describes how this fork adapts global SMART Guidelines content for Ethiopian Ministry of Health use.

For Ethiopia, WHO recommendations are interpreted and adapted in line with Ministry policies, national HIV programme procedures, local terminology needs, and the digital health tools used across service delivery and reporting workflows.

This implementation guide provides Ministry-customized content required in digital systems, independently of a specific software application, so that implementers can align systems with Ethiopian HIV programme requirements.

WHO guidelines articulate and endorse rigorously tested recommendations for health interventions. The Ethiopian Ministry of Health customization preserves the relevant global evidence base while identifying how the content should be represented for local programme, reporting, and interoperability needs.

For more on layers of knowledge representation and how they are used in WHO’s SMART Guidelines approach, see [WHO’s SMART Guidelines](https://www.who.int/teams/digital-health-and-innovation/smart-guidelines) and this [Lancet article](https://www.thelancet.com/journals/landig/article/PIIS2589-7500(21)00038-8/fulltext).

The standards-based technical artifacts in this implementation guide are at the third layer of knowledge representation (L3: Machine-readable recommendations). It provides code necessary for software developers to incorporate standardized Ministry-approved HIV logic into digital systems, testable for conformance to standards and fidelity to the adapted recommendations. A standards-based technical implementation guide builds on operational (L2) content by mapping data elements to value sets and Health Level Seven International Fast Healthcare Interoperability Resources (FHIR) standards. Alongside data standards from L2, this allows for semantic and syntactic interoperability at scale. The logic derived from guidelines may include clinical decision support and calculations for performance indicators encoded in Clinical Quality Language (CQL). This ensures that key indicators can be consistently extracted to support patient care, case surveillance, and programme monitoring in Ethiopia.

The fourth layer (L4: Executable reference applications and services) focuses on software applications and services within the digital health ecosystem. For Ethiopia, L4 implementations should accurately represent Ministry-approved operational and functional requirements, address local user and health system needs, and use the machine-readable data and calculations documented in the L1-L3 layers. Additional products at this layer may include terminology services, reusable software libraries, software development kits, application programming interfaces, and services that support updates to FHIR content across subscribed digital systems.
